# ChessHindsight

*See your own chess clearly, after the fact.*

A local desktop app for analyzing chess games in bulk. It pulls your games from
Chess.com and Lichess (and any PGN file you point it at), stores them in SQLite,
and answers questions that the built-in tools on those sites don't:

- **Which positions do I keep ending up in?** — ranked by frequency, with your
  score in each, so a common position you score badly in stands out.
- **How does a specific player play?** — yours, a friend's, or a pro's, with a
  full opening tree filtered any way you like.
- **What's my record against one particular person?** — broken down by time
  control *and* by exact clock (3+0 vs 3+2 counted separately), with win rates.

## Setup

Run `setup.bat` once. It creates a virtual environment and installs the three
dependencies (`chess`, `requests`, `pywebview`).

Then launch with **`ChessHindsight.bat`**.

## Building a standalone .exe

Run **`build.bat`**. It produces a single **`dist\ChessHindsight.exe`** (~14 MB)
with Python, the libraries and the whole UI bundled inside — no virtual
environment needed to run it. Stockfish is copied to `dist\stockfish\` rather
than bundled, since it is ~109 MB on its own.

The resulting folder is self-contained and portable:

```
dist\
  ChessHindsight.exe        the app
  stockfish\               engine (optional)
  data\                    created on first run: database, settings, log
```

`data\` is deliberately written *beside* the exe rather than inside the bundle —
a one-file PyInstaller app unpacks itself to a temp directory that is deleted on
exit, so anything written there would vanish. Copy the whole `dist\` folder to
move the app and its history somewhere else.

Since the exe is unsigned, Windows SmartScreen may warn on first launch —
"More info" then "Run anyway".

**Note:** the build overwrites `dist\ChessHindsight.exe`, so close the app first
or the build fails with "Access is denied".

## Sending it to someone else

Run **`package.bat --with-engine`**. It produces a single self-contained
**`dist\ChessHindsight-windows-with-stockfish.zip`** (~88 MB): the exe, the
engine, and instructions. The recipient unzips it and double-clicks — nothing to
download, nothing to configure.

Plain **`package.bat`** builds the same thing without the engine
(`dist\ChessHindsight-windows.zip`, ~15 MB) for when bandwidth matters more than
convenience; the recipient then fetches Stockfish themselves.

|                          | `package.bat` | `--with-engine` |
| ------------------------ | ------------- | --------------- |
| Zip size                 | ~15 MB        | ~88 MB          |
| Recipient needs Stockfish| yes           | no              |

Each variant ships the matching `READ ME FIRST.txt` from `packaging\` — one
sends the reader off to stockfishchess.org, the other tells them it is already
there. Both cover the SmartScreen warning the unsigned exe triggers.

Do **not** just zip `dist\`. That folder contains `data\`: the database of every
game ever synced, plus a `config.json` holding the account names behind them.
`package.bat` stages a clean copy rather than compressing `dist\` in place, then
re-opens the finished zip and refuses to hand it over if any `data\` entry,
database, log or `config.json` made it in.

`--with-engine` copies the **whole** `stockfish\` folder, not just the binary.
Stockfish is GPL-3, so conveying the executable obliges us to convey its
corresponding source too — and `src\` is under 1 MB against a 109 MB binary, so
mirroring the upstream archive verbatim is both the cheapest and the most
defensible way to satisfy that.

Either way the zip is too big to attach to an email, so send a link — Google
Drive, Dropbox, WeTransfer.

### The icon

`assets\icon.ico` is generated by `tools\make_icon.py` rather than hand-drawn,
so it can be re-tuned by editing values. It renders a knight on a walnut tile at
seven sizes; 16 and 24 px get a simplified, higher-contrast treatment instead of
a blind downscale, because detail that reads at 256 px is mud at 16.

```
.venv\Scripts\python.exe tools\make_icon.py
```

That rewrites `assets\icon.ico` and an `assets\icon-preview.png` contact sheet
showing every size on light and dark backgrounds. Rebuild the exe to pick it up.
Requires Pillow (`pip install pillow`); the committed `.ico` means a normal
build does not need it.

The `.ico` is written by hand rather than by Pillow's ICO encoder, because that
encoder PNG-compresses **every** size. Windows Explorer only reliably decodes
PNG icon entries at 256x256 — below that it expects a classic BMP/DIB, and
falls back to a generic icon when it finds PNG. So sizes under 256 are written
as DIB and only 256 as PNG.

If Explorer still shows a stale icon after a rebuild, its cache is holding on:

```
ie4uinit.exe -show
```

## Themes

**Settings → Appearance** has twelve themes, applied instantly and remembered.
Each sets the whole palette including a default pair of board squares.

| Theme | |
|---|---|
| **Walnut** | warm dark, amber accent, wooden board — the default |
| **Slate** | cool dark, blue accent, grey-blue board |
| **Midnight** | near-black, violet accent |
| **Forest** | dark green with a tournament green/buff board |
| **Nord** | muted arctic blue-grey |
| **Ocean** | deep teal, cyan accent |
| **Ember** | charcoal with a warm orange accent |
| **Paper** | light, neutral |
| **Sepia** | light, warm parchment |
| **Contrast** | pure black and white, maximum legibility |
| **Dark** | plain dark mode — neutral grey, blue accent, no house style |
| **Light** | plain light mode — white, neutral grey, blue accent |

Adding another is two edits: a `:root[data-theme="name"]` block in
`web/style.css` defining the 13 palette variables, and one row in the `THEMES`
table in `web/app.js`. The picker builds itself from that table.

### Board colours

Chosen separately from the theme, because wanting a grey interface and a green
board is an ordinary preference and tying the two together made it unreachable.
**Follow theme** is the default and keeps whatever squares the theme defines.

A board palette is one line of CSS overriding exactly two variables:

```css
:root[data-board="green"] { --light-sq: #ffffff; --dark-sq: #769656; }
```

That "exactly two" is enforced by the test suite — a board colour must never be
able to restyle the interface.

## Piece styles

Independently of the theme, **Settings → Appearance → Piece style** offers four:

| Style | |
|---|---|
| **Classic** | outlined on both sides — black stays legible on dark squares in every theme |
| **Traditional** | black outlined in black, the way a printed diagram looks |
| **Solid** | flat silhouettes, no outline |
| **Bold** | heavy outlines; pairs with the Contrast theme |

The pieces are SVG ([web/pieces.js](web/pieces.js)) drawn on a shared 45×45 grid.
All four styles are presentation over that one set of geometry — each is a block
of CSS custom properties, which is why the picker previews can show their own
style rather than the active one.

## First run

1. Open **Settings** and add your accounts (Chess.com and/or Lichess).
2. Go back to **Dashboard** and press **Sync accounts**.
   The first sync downloads your whole history; later syncs only fetch what's new.
3. Your username is filled into the filter bar automatically. Everything else
   keys off that.

To analyze someone who isn't you — a friend or a pro — either add their account
under Settings and sync it, or just type their username into the **Player** box
if their games are already in the database (they will be if you've played them).

### Importing PGN

**Import PGN…** on the Dashboard takes a single `.pgn` file or a whole folder of
them. Games exported from Lichess or Chess.com are recognized by their site IDs,
so importing a PGN of games you already synced won't create duplicates.

## The views

| View | What it answers |
|---|---|
| **Dashboard** | Overall record, split by time control; most-played opponents |
| **Explorer** | Move-by-move opening tree from any position, with your score per move |
| **Positions** | The positions you reach most often — sort by frequency or by worst score |
| **Head-to-head** | You vs one specific player: games, win rates, per-time-control splits |
| **Openings** | Performance grouped by ECO code |
| **Games** | Every game matching the filter, paginated |

The filter bar at the top applies to every view: player, colour, opponent, time
control, **period** (All time / last month / 3 / 6 / 12 months, or an explicit
From–To range), source, rated/casual, opponent rating band, and ECO.

The period buttons and the From/To date boxes drive the same filter — clicking a
preset fills in the From date, and typing a date clears the presets.

## Engine analysis

Stockfish lives in `stockfish/` and is detected automatically (the official
Windows builds have CPU-suffixed names like `stockfish-windows-x86-64-avx2.exe`,
so detection is by pattern, not exact filename). To use a different binary, set
its path in **Settings → Engine**.

The Explorer has an **evaluation bar** beside the board showing a traditional
score in pawn units from White's point of view: `+1.20` means White is better by
about a pawn and a bit, `-0.35` means Black is slightly better, `0.00` is equal,
and `#3` means mate in three. The bar fills toward whoever stands better.

**Auto-evaluate** (on by default) evaluates each position as you browse the
tree. Every evaluation is cached in the database permanently, so a position is
analyzed once and thereafter returns in about a millisecond — browsing the same
opening repeatedly costs nothing. Turn it off if you want the engine to stay
quiet, and use **Evaluate** for one-offs.

On the Positions view, **Evaluate all** runs the engine over every position
shown and tags each card with its score — so you can see at a glance whether a
position you keep losing is actually bad, or whether you're just playing it
badly.

## Command line

Everything the GUI shows is also available headlessly, against the same database:

```
.venv\Scripts\python.exe cli.py summary
.venv\Scripts\python.exe cli.py account add lichess YourName
.venv\Scripts\python.exe cli.py sync
.venv\Scripts\python.exe cli.py stats --player YourName
.venv\Scripts\python.exe cli.py h2h --player YourName --opponent FriendName
.venv\Scripts\python.exe cli.py h2h --player YourName --opponent FriendName --tc blitz
.venv\Scripts\python.exe cli.py tree --player YourName --color white e4
.venv\Scripts\python.exe cli.py positions --player YourName --worst
.venv\Scripts\python.exe cli.py sync --pgn C:\path\to\games.pgn
```

Add `--db <path>` to any command to use a different database file.

`app.py --serve` runs the web UI without the desktop window, at
<http://127.0.0.1:8731> — handy for debugging in a real browser with devtools.

## How it works

```
chesshindsight/
  config.py     settings + account list, persisted to data/config.json
  db.py         SQLite schema and connection handling
  sources/      one adapter per origin, all producing NormalizedGame
    chesscom.py   public API, synced at monthly-archive granularity
    lichess.py    ndjson export, synced by exact timestamp
    pgnfile.py    local files; game ids are content hashes, so re-import is safe
  ingest.py     NormalizedGame -> rows + position index
  query.py      the shared GameFilter, compiled to SQL once and reused
  stats.py      win rates, time-control splits, head-to-head
  tree.py       position-frequency tree and "positions reached most often"
  engine.py     Stockfish with a persistent process and a persistent eval cache
  sync.py       incremental sync orchestration
  api.py        the app's whole API surface, transport-agnostic
  server.py     loopback HTTP transport
web/            frontend (no build step, no external dependencies)
app.py          desktop entry point
cli.py          command-line entry point
```

Two design points worth knowing:

**Position indexing is capped.** Every game's full move list is stored, but
positions are indexed for tree queries only up to `max_indexed_ply` (default 40
plies = move 20). That bounds the index while covering the openings and early
middlegame, which is what frequency questions are actually about. Raising it in
Settings and pressing **Reindex** rebuilds from stored moves — it never
re-downloads anything.

**The desktop window and the browser run identical code.** `app.py` starts the
same loopback HTTP server the `--serve` flag does and points a native WebView2
window at it, so there is one code path to reason about and test.

## If it freezes or crashes

Every run writes to **`data\chesshindsight.log`** (next to the exe, or in the
project folder when run from source). It captures startup, unhandled exceptions
on any thread, JavaScript errors, and native crashes.

It also detects freezes. The UI sends a heartbeat every 4 seconds; if those stop
for 12 seconds while the process is alive, a watchdog writes a stack trace for
**every thread** into the log. Windows' own "Application Hang" event tells you
nothing about the cause — this does.

If the app hangs again, send `data\chesshindsight.log`. Look for
`no heartbeat from the UI` — the dump immediately after it names the thread that
was stuck and the exact line it was stuck on.

## Notes

- The database lives in `data/chesshindsight.db`, settings in `data/config.json`.
  Both are gitignored. Back up that folder and you've backed up everything.
- The server binds to `127.0.0.1` only.
- A Lichess API token (Settings) is optional; it raises the export rate limit,
  which only matters for accounts with many thousands of games.

### Before making this repository public

Two things need attention first — both fine for a private, personal repo:

1. **Piece sets.** `web/piecesets/` carries 41 sets taken from Lichess. Several
   are CC BY-NC-SA (non-commercial) and a handful sit under Lichess's own
   "Exceptions (non-free)" heading. `assets/NOTICE.md` records which is which,
   set by set. A public release should drop the non-free ones.
2. **Licence headers.** The source files carry no per-file headers yet.

The opening-name book (`assets/openings.tsv`) is safe either way: it is built
from [lichess-org/chess-openings][co], which is CC0.

[co]: https://github.com/lichess-org/chess-openings
